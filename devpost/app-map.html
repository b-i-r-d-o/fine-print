Fine Print: App Map

A one-page guide to how Fine Print fits together: what the main pieces are, how one action travels through the code, and where to start when you want to change something.

What it is

Fine Print is a phone web app with an AI agent for personal agreements. You upload or photograph a contract. The agent reads it, files it, lists its dates and contacts, asks a plain question about where you stand, and helps with the next step, like drafting an Alberta move-out notice or suggesting automatic mortgage payments. It's guidance, not legal advice.

The app

public/ holds the screens, chat, themes, calendar and contact files, and the notice PDF. Your agreements and chats are saved on the phone itself.

The helper

api/agent.js runs on Vercel and holds the hidden API key. It adds the agent's instructions, asks Claude, and checks the reply before passing it on.

The instructions

lib/prompts.js holds the agent's voice and the Alberta tenancy rule, word for word. lib/ai.js is the only file that knows which AI is used.

One action, start to finish: storing the mortgage

You upload the mortgage, tap Store, and a blue "💡 Suggested next step" card appears. Here's the path it takes.

The route through the code

A reference route: three stops, using names you can search for in each file.

  1. The agent's instructions lib/prompts.js, search "suggested_action" inside READ_PROMPT Tells Claude what to send back and in what shape: a short label and a how, worded from the contract's own payment day and amount.
  2. The helper checks the reply api/agent.js, search export function validRead The reply has to have the fields the app needs. The suggestion is kept only if it has a real label, and it's trimmed to a sensible length. Otherwise it's dropped, and a bad reply is retried once.
  3. The app decides what's shown public/app.js, search function handleReadReply, then function suggestionCheck After Store, the app files the agreement and shows the blue card. The checkbox, How? and keeping list, page and chat in sync are plain app code, with no AI involved.

A practice to reuse

Split every agent feature three ways: what the AI produces, how it's checked, and what the app does with it.

Fine Print's spec set the rule early: the AI decides what to say; the app decides what's allowed. The suggested-action feature followed it exactly: a field in READ_PROMPT, a check in validRead, and the card and checkbox in public/app.js. The same split is why the Alberta rule is written into the instructions word for word, and why the notice dates come from noticeEndDate in code, never from the AI.

On another agent project, write those three lines for each feature before building it. It shows early what the AI must return, what could go wrong, and what stays fixed whatever the AI says.

Run it again

Live: open the Vercel link on your phone, or add it to your home screen. Locally: in the project folder run node dev-server.js and open http://localhost:3000. Without an API key it runs in labelled practice mode with canned replies.
