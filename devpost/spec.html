The agent rule of thumb

What Fine Print is

A comprehension and guidance tool, not legal advice. Said plainly on the Welcome screen, on the notice view and in the README. In the chat, just one small, subtle caption.

The AI does
  • Reading the contract
  • Understanding "no, I want to move out"
  • Explaining the rule in casual words
  • Writing the notice wording
  • Summarizing the mortgage dates
The app does
  • Sign-in, profile, every button
  • The home list and saving
  • The notice end date, calculated in code
  • Making the PDF
  • Deciding which buttons may appear

What it's made with

App: plain HTML, CSS and JavaScript

No framework and no build step, so every file stays readable for a first-time builder. Tradeoff: a bit more hand-written code, which is fine at this size.

Helper: one Vercel Function

Node.js on Vercel's free Hobby plan, using the built-in fetch to call the AI. There's no AI library, so switching providers later touches one file. Vercel Functions docs

AI: Claude, with Gemini possible later

Sonnet 5.5 for the careful first read, Haiku 5.5 for quick chat and drafting. Likely under $5 for the whole hackathon. Your plan to switch to Gemini's free tier later only changes lib/ai.js. Messages API · Pricing

PDF: jsPDF 2.5.1

Makes the notice PDF right on the phone. jsPDF docs

Where it runs and how someone tries it

From GitHub to your home screen

  1. Create a free Vercel account by signing in with GitHub.
  2. Get a Claude API key from the Claude Console and add a few dollars of credit.
  3. In Vercel: Add New → Project → import b-i-r-d-o/fine-print → add ANTHROPIC_API_KEY → Deploy.
  4. Open the Vercel link on your phone → browser menu → Add to Home Screen.
  5. Tap the Fine Print icon. Every push to GitHub redeploys automatically.
Practice mode, for building only

While building, I can run the app without the key using canned replies clearly labelled "PRACTICE MODE." You never paste your key into chat. The demo is always recorded on the real link with real AI.

Look and feel

Names are proposals you can rename during the build.

Warm beige, soft taupe, deep brown-grey text, a muted sage or clay accent. Clean sans-serif. Calm and roomy.

Midnight

Near-black, deep navy surfaces, crisp blue accent, white text.

Heirloom

Cream paper, maroon and olive, serif print-style font. The demo ends in this one.

Everywhere

Female-friendly, feels like messaging rather than legal software, thumb-sized buttons, casual agent voice with a few emojis, and small honest "Demo" and "Coming soon" tags.

Important failure modes

Where it could break in front of someone

AI is slow"Reading your agreement… 📄" with a gentle animation. After 60 seconds, a retry button.
AI reply in the wrong formatThe helper retries once automatically, then "Something went wrong reading that — try again?"
Blurry or huge uploadPhotos are shrunk automatically. Unreadable: "This photo is unfocused 📷 — please retake it." A PDF that's too big: try photos of the key pages.
Key missing or out of credit"The AI isn't connected right now."
Wrong notice end dateAvoided by calculating it in code and checking it with test dates.
What was simplified and why

Engineering judgment on the page

  • Demo sign-in instead of real accounts. Accounts don't prove the idea.
  • Saved on the phone instead of a cloud database. One user, one demo.
  • Filed by name and facts, not by keeping the original file. Phone storage is too small for PDFs; cloud storage is already on the Later list.
  • Read once, then only facts are sent on, so follow-up chat is fast and cheap.
  • End date calculated in code, because legal correctness shouldn't rest on AI arithmetic.
  • Practice mode for building, never for the demo.
Decisions and open issues

Your calls, and what to check early

  • Guidance, not legal advice: stated in the app, the agent's instructions and the README. Your call.
  • Vercel hosting: you agreed.
  • Claude for the demo, maybe Gemini later: your choice. Only one file changes.
  • No framework: recommended for readability, and you accepted it.
  • Design details: you expect strong first-pass choices and will fine-tune after seeing them.
  • Your learning approach: see it, then ask. We'll pause at the first screen on your phone, the first real AI read, and the notice PDF.
