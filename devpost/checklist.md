# Build Checklist

Build mode: learn

**About verification in this build:** this cloud workspace can run the app and helper locally in practice mode, but it can't reach Vercel and has no API key (the key never comes into chat). So the mechanical checks run locally in practice mode, with real code paths, schema checks and browser screenshots. The **real-AI behaviour** is confirmed by Joann on her phone at the live Vercel link, as part of each learner check.

## Revisions

- **Cut-off or missing pages are flagged** (Joann's slice 4 check: a partial photo of page 1 wasn't flagged, because it was readable, just incomplete). The read reply now has `photo_issue`, a plain sentence such as "Page 1 looks cut off at the bottom", or a note that a page seems to be missing. The helper only passes it through for photos. Before filing, the agent says "Heads up 📷 …" and offers **📷 Retake** (the tray reopens with the pages, so the bad one can be removed and retaken) or **Keep going** (filed with what it could read).
- **Add a page to a photographed agreement** (Joann: "if I forgot a page", it should update with any added contacts and dates). New behavior, agreed as a final-review addition. The agreement page's photographed pages get **📷 Add a page**, which opens the camera tray in the chat with the stored pages already in it. **Done, update it** re-reads all the pages together (in page order), keeps everything already known, and adds only the new dates and contacts. The agent lists just the new ones and offers to put any new dates in the calendar. Only photographed agreements get this button, since PDF uploads are already complete files.
- **Photographed pages saved in the document's real order** (Joann's slice 4 check: Next page and Done worked, and she deliberately shot page 2 first. The AI read it correctly, but View original showed the photos in the order she took them). The helper now labels the photos "Photo 1, Photo 2…" and asks the AI for `page_order`, which it checks covers each photo exactly once. The app reorders the photos before saving them, and keeps the order taken if the answer is missing or invalid.
- **Calendar opens inside the app** (Joann, Android: the .ics only downloaded, so she had to leave the app, find it in Downloads and open it). Now **Yes, add them**, the agreement page button and the calendar file card all open the calendar file in the app's viewer. Each event shows its date in words (repeats too) and an **Add to Google Calendar** button that opens the calendar with the event filled in. **Save calendar file** stays for iPhone and Outlook, which add the whole file at once. Get PDF in the chat also opens the notice in the app instead of downloading it.
- **File cards in the chat** (Joann): when the agent makes the notice PDF or a calendar file, the chat now shows it like an attachment (icon, file name, Open). Tapping the PDF opens it in the in-app viewer with Save a copy, and tapping the calendar file opens it in the phone's calendar again. The cards stay in the saved chat.
- **Add to calendar** (Joann, before the final check): after Store, the agent offers to add the agreement's upcoming and repeating dates to the calendar as an .ics file. The agreement page and the move-out notice have the same button, and a linked Google or Outlook calendar is coming soon. We chose a file over a linked calendar because it needs no sign-in or calendar permissions and works on both iPhone and Android. Also added a fictional two-page employment contract sample (abattoir employer) for the camera check, and made all sample addresses obviously fictional (TXX 0ZZ, with a legal land description on the mortgage).
- **Originals are now kept and viewable** (Joann: "I can't open up the PDFs"). The spec had chosen not to keep originals because local storage is too small. Now they're stored in IndexedDB on the phone and shown with an in-app viewer (PDF.js 3.11.174, bundled), with Save a copy as a fallback. Opening a PDF in a new tab proved unreliable (blank in testing; phones vary), hence the in-app viewer. Older agreements get their copy kept when re-uploaded, and Delete and Reset demo remove originals.
- Slice 4 built: the camera opens the back camera one page at a time into a page tray in the chat (thumbnails, remove a page, Next page, Done, Cancel, framing tips), up to 8 pages. Photos are shrunk in steps until the whole request fits (3 phone photos of ~10 MB went out as ~1 MB). Unreadable photos get a retake prompt with a Retake button. Phone-native framing guides aren't possible from a web page, so tips are shown instead.
